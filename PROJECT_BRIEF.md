# PROJECT_BRIEF.md

## Project Name

Badis Cloud & DevOps Freelance Website

## Project Type

Standalone freelance landing page.

This project is separate from the existing portfolio website:

- Existing portfolio: `https://portfolio.badismerakchi.com/`
- New website: dedicated freelance service website
- Repository: separate GitHub repository
- Goal: commercial conversion, not CV presentation

## Objective

Create a premium one-page website to present and sell freelance Cloud, DevOps, and Platform Engineering services.

The website must help visitors quickly understand:

1. Who Badis is
2. What problems he solves
3. What services he offers
4. Why he is credible
5. How to contact him

Primary conversion goal:

> Get qualified prospects to contact Badis for freelance missions.

Secondary goals:

- Create a more commercial online presence than the existing portfolio
- Support outreach and networking
- Support LinkedIn profile traffic
- Support freelance applications and referrals
- Build trust with Swiss and French-speaking clients

## Recommended Website Structure

The first version should be a one-page website.

### 1. Hero Section

Purpose:

- Explain the offer immediately
- Build trust
- Push visitors toward contact

Required elements:

- Strong headline
- Short supporting paragraph
- Primary CTA
- Secondary CTA
- Location / availability indicator
- Optional short credibility line

Example intent:

> Consultant Cloud & DevOps freelance basé près de Genève.  
> J’aide les entreprises à automatiser, fiabiliser et industrialiser leurs infrastructures cloud et leurs workflows de livraison.

### 2. Services Section

Purpose:

- Present clear offers
- Help prospects recognize their problem

Required elements:

- 3 or 4 service cards
- Short description per service
- Concrete deliverables or outcomes
- No long technical paragraphs

### 3. Why Work With Me Section

Purpose:

- Explain why Badis is credible

Required elements:

- Oracle Geneva experience
- Swiss enterprise context
- Cloud / DevOps background
- Practical delivery mindset
- Clear communication

### 4. Method Section

Purpose:

- Show a simple collaboration process

Recommended steps:

1. Discovery call
2. Technical audit or need assessment
3. Implementation roadmap
4. Delivery, documentation and handover

### 5. About Section

Purpose:

- Humanize the page without turning it into a CV

Should include:

- Badis is based near Geneva
- Cloud and DevOps consultant
- Former Oracle Geneva experience
- Strong interest in infrastructure, automation and platform reliability
- Focus on useful delivery, not buzzwords

### 6. Proof / Experience Section

Purpose:

- Build confidence

Possible content:

- Technologies
- Past environments
- Selected project types
- Existing GitHub / portfolio links
- Certifications

Avoid confidential client details.

### 7. Contact Section

Purpose:

- Convert visitor into lead

Required elements:

- Clear invitation to contact
- Email
- LinkedIn
- Contact form or mailto fallback
- Expected response time
- Type of missions accepted

Recommended wording:

> Décrivez brièvement votre besoin, votre contexte technique et votre horizon de démarrage. Je vous répondrai rapidement pour voir si je peux vous aider.

### 8. Footer

Required elements:

- Name
- Role
- Location
- LinkedIn
- GitHub
- Email
- Legal links if needed later

The website should be strongly inspired by FyberHub in terms of:

- Dark background
- Strong hero section
- Commercial wording
- Service blocks
- Process section
- Contact-focused structure
- Premium independent consultant feeling

However, the content must be adapted to Cloud, DevOps and Platform Engineering.

Do not copy:

- Exact text
- Logo
- Brand name
- Images
- Source code
- Unique visual assets

## Tone

Main language:

- French

Tone:

- Direct
- Professional
- Confident
- Clear
- Commercial
- Pragmatic

Avoid:

- Excessive technical jargon
- Long explanations
- Generic corporate phrases
- Overpromising
- Buzzword stacking
- Weak or hesitant language

Good tone example:

> Des infrastructures reproductibles, documentées et plus simples à maintenir.

Bad tone example:

> Je révolutionne votre transformation digitale grâce à une synergie DevSecOps cloud-native scalable.

## Success Criteria

The first version is successful if:

- The visitor understands the offer within 5 seconds
- The page feels premium and professional
- The services are clear
- The page does not feel like a CV
- The CTA is visible and repeated
- The contact path is obvious
- The site works well on mobile
- The site can be deployed statically
- There is no fake or exaggerated claim
- The design is close in spirit to FyberHub, but adapted to Badis
